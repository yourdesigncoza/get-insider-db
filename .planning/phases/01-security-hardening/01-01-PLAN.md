<task type="auto">
  <name>Task 1: Fix SQL injection in cluster signal queries</name>
  <files>src/analytics/cluster_buys.py</files>
  <action>
Replace all f-string INTERVAL interpolations with parameterized queries.

**Current vulnerable pattern (lines ~225-283):**
```python
INTERVAL '{window_interval} day'
```

**Secure replacement pattern:**
```python
INTERVAL '1 day' * :window_interval
```

Locations to fix (search for `INTERVAL '{window_interval}`):
1. Line ~225: `(b.transaction_date - INTERVAL '{window_interval} day')::date AS window_start`
2. Line ~231: `b.transaction_date - INTERVAL '{window_interval} day' AND b.transaction_date`
3. Line ~237: Same pattern in COUNT subquery
4. Line ~243: Same pattern in unique insiders subquery
5. Line ~249: Same pattern in shares subquery
6. Line ~255: Same pattern in value subquery
7. Line ~283: Same pattern in top_insiders subquery

**Implementation:**
1. Replace each occurrence of `INTERVAL '{window_interval} day'` with `INTERVAL '1 day' * :window_interval`
2. Add `"window_interval": window_interval` to the params dict (around line 311)
3. Ensure window_interval is passed as integer (it already is per function signature)

**Why this works:** PostgreSQL allows multiplying INTERVAL by integer:
- `INTERVAL '1 day' * 10` equals `INTERVAL '10 day'`
- The :window_interval placeholder is safely bound by SQLAlchemy

**Do NOT:**
- Change the query logic or structure
- Add any new parameters beyond window_interval
- Modify filtering conditions
