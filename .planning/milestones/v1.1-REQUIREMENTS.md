# Requirements: get-insider-db

**Defined:** 2026-02-11
**Core Value:** Accurate, actionable cluster buy signals from SEC insider trading data

## v1.1 Requirements

Requirements for Result Quality 01. Each maps to a roadmap phase.

### Filtering

- [x] **FILT-01**: Clusters with fund ratio exceeding max_fund_ratio threshold are excluded from scan results
  - *Outcome: Strict exclusive boundary (< operator). Config-driven CLI defaults. 9 boundary tests.*
- [x] **FILT-02**: Rows with N/A or missing tickers are excluded from scan results
  - *Outcome: SQL-level filtering in all 3 query locations. 6 invalid literals excluded. 18 unit tests.*

### Data Integrity

- [x] **DATA-01**: Window spans in results do not exceed the configured window_days parameter
  - *Outcome: Span validation in merge logic. Oversized overlaps kept as separate events. 11 regression tests.*
- [x] **DATA-02**: issuer_cik is populated for every row in scan output
  - *Outcome: SQL view schema extension. Zero Python changes. 10-digit zero-padded CIK strings. 9 tests.*
- [x] **DATA-03**: avg_sale_to_purchase_ratio computes correctly (non-zero when insiders have both sales and purchases in lookback)
  - *Outcome: New insider_trade_signals view (P+S). Batch-loaded sales data. Graceful fallback. 8 tests.*

### Output Quality

- [x] **OUT-01**: Duplicate ticker entries across different windows are handled with explicit strategy (merge, flag, or deduplicate)
  - *Outcome: --deduplicate CLI flag. Pure-function utilities. Console annotations. 10 tests.*
- [x] **OUT-02**: All floating-point fields in JSON export are rounded to 2 decimal places
  - *Outcome: FLOAT_FIELDS_TO_ROUND constant (5 fields). Copy-then-round pattern. 5 tests.*
