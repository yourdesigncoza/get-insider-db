# Milestone v1.2: CIK-Based Enrichment

**Status:** SHIPPED 2026-02-12
**Phases:** 15-17
**Total Plans:** 4

## Overview

Replace volatile ticker-based lookups with permanent CIK identifiers throughout enrichment pipeline. Tickers change (FB→META), CIK is forever.

## Phases

### Phase 15: CIK-to-Ticker Mapping
**Goal**: Database stores authoritative CIK-to-ticker mapping from SEC data
**Depends on**: Nothing (milestone foundation)
**Plans**: 1 plan

Plans:
- [x] 15-01: Mapping table DDL, population in data load, CikTickerMapper service + tests

**Details:**
- Created `issuer_cik_ticker_map` table (CIK TEXT PK, ticker, issuer_name, last_seen_date)
- Populated 8,982 CIK-ticker mappings from form345_submission
- Built CikTickerMapper service with O(1) in-memory cache (~300KB)
- 16 new tests, 98.8% CIKs maintain zero-padding
- ON CONFLICT upsert ensures latest filing's ticker wins

### Phase 16: Schema Re-keying
**Goal**: Market data organized by permanent CIK identifier, not volatile tickers
**Depends on**: Phase 15 (needs mapping table)
**Plans**: 1 plan

Plans:
- [x] 16-01: Migration SQL scripts + schema.sql DDL update for CIK-based keys

**Details:**

### Phase 17: Enrichment Pipeline Migration
**Goal**: Price enrichment works with CIK as primary key, tickers resolved for API calls
**Depends on**: Phase 16 (needs re-keyed schema)
**Plans**: 2 plans

Plans:
- [x] 17-01: Sync enrichment CIK migration (enrich_clusters_with_price.py)
- [x] 17-02: Async enrichment CIK migration (enrichment_service.py + enrich_clusters_async.py)

**Details:**
- All DB cache queries use WHERE issuer_cik (0 ticker-based WHERE clauses)

- EnrichmentStats tracks resolved, missing_cik, unmapped_cik counts
- Progress logs display "CIK (TICKER)" format

## Milestone Summary

**Key Decisions:**
- CIK as primary identifier (tickers change, CIK is permanent)
- Latest ticker per CIK (simple, covers 99% of cases)
- CIK stored as TEXT (preserves zero-padding for SEC API compatibility)
- Fresh start for market data (TRUNCATE + re-fetch on enrichment)
- Strict CIK exclusion (no CIK or unmapped CIK = exclude entirely)
- In-memory mapping cache (8,982 entries = ~300KB, O(1) lookups)
- Pre-validation at CLI entry point (exclude bad data before expensive operations)

**Issues Resolved:**
- Ticker-based data fragmentation eliminated (FB→META scenario)
- Sync enrichment cluster exclusion bug fixed (commit a5c5922)

**Issues Deferred:**
- Historical ticker tracking (not needed — latest ticker sufficient)
- pytest-asyncio plugin for async enrichment tests (test infrastructure, not code)

**Technical Debt Incurred:**
- Phase 17 VERIFICATION.md contains stale gap reference (cosmetic)
- Async enrichment tests need pytest-asyncio plugin installation
